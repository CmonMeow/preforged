Movement, patrol, pursuit and return

  Side world1075->1078 records guard27 in epoch1/lifetime1:27:1 displacing250
    units in1000ms. Other scripted actors show multi-thousand-unit corrections.

Implementation requirements justified by these observations
  1. Instance + spawn-generation identities for all actor, action and target state.
     Cancel/clear references on actual despawn/death; never inherit agent-ID state.
  2. Separate profiles for hostile proximity acquisition (including disabled),
     scripted combat, patrol/wander, party follower, pet controls, minion and
     summoned ally. Per-profile interruption/owner-follow priority is necessary.
  3. Keep cast/start/finish/interruption, projectile arrival, damage and owner
     credit as separate events. Retargeting must not transfer an in-flight action.
  4. Track NPC resources server-side; missing public resource evidence is unknown.
     Each loadout/profile needs reviewed capacity, costs and regeneration.
  5. Store original home/patrol context separately from current pursuit position;
     exact leash distances are unproven and require reviewed configuration.
  6. Do not derive quest eligibility, hostility, invulnerability, AI ownership or
     spawn timing from name, model, visibility, or normalized allegiance alone.

Validation limits
  Epoch tick conversion uses median(tick_ms-instance_ms) from observed anchors;
    side capture anchor spreads reach806ms. Loading can briefly report tiny
    instance_ms before resuming a persistent outpost clock. Those transient
    samples are excluded; overlapping epoch windows fail closed.
  NPC identity joins allow at most1500ms sample skew and reject known despawn
    gaps. Unknown mid-stream lifetimes remain unknown and are excluded from
    retarget/lifetime motion claims. Exact geometry needs packet movement replay.

Native companion policy slice (2026-10-12)
  src/runtime/gw_companion_policy.h is an independently testable decision module.
  tests/companion_policy.cpp covers follower and guard-pet recall/hysteresis,
    Heel immediate return, Attack lock restoration/range, committed minion and
    summon combat, target/source/owner generation changes, stale/cross-instance
    target commands, uncertified triggers, ambiguous actor snapshots, dead actors,
    missing/NaN/invalid configuration, and pending-action cancellation.
  All test distances are synthetic fixtures, NOT retail constants.
  Profiles: friendly_follower, ranger_pet, minion, summoned_ally.
    Following distance start/stop, friendly combat-break distance, pet Guard
    combat-break distance, and pet Attack-lock range are optional explicit config.
    Required missing values return unsupported_configuration; none has a default.
  Minion/summon retain a valid engaged target despite owner distance or a new
    owner target, and resume following/acquisition when it becomes invalid/dead.
    Summon's rare exceptions are not recovered; this is the supported committed
    profile, not a claim to represent every summoned ally's script.
  Acquisition is a caller-certified event, not an automatic nearest-foe search.
    Pet Guard accepts owner_attack/adjacent_owner_threat; minion/summon accept
    owner_attack/proximity; friendly follower accepts owner_attack/assisted_combat.
    The caller must validate the trigger using reviewed actor-specific rules.

Root integration contract
  Construct one Controller per authoritative NPC lifetime and provide Actor keys
    {instance,generation,id}; bind to current owner lifetime. Command validation
    requires one tick with the current binding first. The caller may tick again
    immediately after a valid pet command to issue its resulting decision.
  Under the instance mutex, build a Snapshot with alive/hostile targets and
    materialized positions. action_ready means the actual action's current
    range, LoS, plane and execution gates pass. Distance must be finite/nonnegative.
    World identity/hostility/ownership are inputs, never inferred from model or
    the observed normalized allegiance byte.
  Apply cancel_pending_action before scheduling new action. It cancels unreleased
    attack/cast intent only; already-released projectiles retain original target,
    caster and credit owner. Follow/pursue decisions request normal pathfinding;
    they do not teleport, serialize packets, or reserve damage.
  Unsupported configuration must stop motion/actions and surface reviewed-content
    diagnostics. It is not permission to insert fallback numbers in world code.
  This module deliberately does not choose skill rotations or threat rankings,
    grant energy, spend costs, pathfind, trigger quest scripts or emit packets.
    Skill/weapon schedulers remain responsible for costs, cooldown, validation at
    release, projectile arrival, damage, and separate actual-caster/credit-owner.
  Owner disappearance is a fail-closed integration guard (idle/cancel), not an
    asserted retail rule about orphaned summons. Explicit owner death policies,
    uncommon summon disengagement and scripted exceptions remain future content.
  No shared CMake/runtime-world files were modified. Root can register
    companion_policy_test from tests/companion_policy.cpp as a standalone target.
