Provenance and admission
  Every input source SHA256 is checked against the original capture audit before
  raw replay. Epoch windows are disjoint; gaps remain unassigned. Decreasing
  packet clocks or lifetime disagreements fail closed. Every action requires an
  observed packet spawn generation and an NPC identity joined by the prior audit.
  A future identity snapshot at or after source despawn/replacement is excluded.
  Packet tick_ms has ties: raw lifetime boundaries additionally use stream line
    order. Four attack20978 precedes despawn20980 despite both tick82283250.
    Timestamp-only half-open packet joins would incorrectly discard this valid
    raw target generation. Snapshot boundaries remain conservatively time-based.
  NPC identity changes divide action sequences even within one packet lifetime.
  Untargeted activation has target=null, never inferred self or current foe.
  All complete raw starts, including unjoined actors, update pending matching.
  Start/end kinds must match and use the same source lifetime. A mismatched end,
  superseding start, despawn or incomplete action packet prevents false pairing.
  Analysis IDs 159/160 are MODERN capture opcodes, not pinned-2022 serialization.

Concrete runtime integration requirements
  1. Use instance+generation+agent keys for caster, target, owner, commands,
     action state, threat candidates and home/patrol state. Resolve current alive/
     hostile/range/LoS/plane gates from authoritative world state, never snapshots.
  2. Keep acquisition events distinct: actual owner weapon attack, skill use,
     called target, pet command, incoming adjacent attack, proximity, group aggro,
     scripted encounter. Selected target alone does not certify an attack trigger.
  3. Add untargeted skills to NPC loadouts/schedulers. A null action target must
     remain null; select actor-specific self-heal/glyph conditions only after
     review. Costs/recharge come from reviewed skill data, not action frequencies.
     Current NPC pools/regeneration remain reviewed content inputs; none defaults
     to infinite energy because public energy updates are missing.
  4. Preserve a pending action's identity and original credit owner. Retargeting
     cancels an unreleased action when appropriate; an already released value
     keeps its old caster/target/credit. Do not migrate it to the new selection or
     infer immediate damage from completion. Projectile and effect validation
     remains the existing authoritative scheduler's responsibility.
  5. Give idle route/wander, pursuit, return-to-content-anchor, party follow,
     pet controls, committed minion/summon and scripted encounter separate policy
     contexts. Store pre-combat idle/home state; repeated sample positions are
     only route research candidates. Keep all unproven thresholds unconfigured.
  6. Do not substitute model/name/allegiance for ownership, hostility, death,
     quest eligibility or invulnerability. Map148's perpetual fight needs an
     encounter controller; it cannot calibrate ordinary respawn/acquisition/leash.

New independently testable native slice
  src/runtime/gw_ai_action_provenance.h has a pending-action Latch with serial,
    Context{caster,optional target,optional credit_owner,kind,skill}, and Released
    values. It uses companion::Actor lifetime keys, emits no packets, chooses no
    targets/skills, mutates no resources and installs no timing/distance defaults.
  Bind source lifetime, then start. Only one noninstant pending action is admitted.
    Cancel/release require the matching serial; source or target generation
    disagreement consumes the stale pending action without releasing. Binding to
    a replacement source clears pending state. Released values remain independent.
  The caller must validate costs/cooldown/liveness/gates at start and release.
    A credit owner's captured lifetime is provenance; death/disappearance does
    not authorize assigning the action to that actor ID's replacement generation.
    World damage/credit code decides whether original owner credit remains valid.
