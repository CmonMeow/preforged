Barrage395 and Volley2144 - implementation and evidence,2026-10-17

Current native source behavior
Barrage uses5Energy,1s base recharge and5..20 bonus-damage endpoints at ranks0..15.
Volley uses5Energy,2s base recharge and1..10 endpoints. Both use native zero
fixed activation/aftercast rows and the existing normal-bow attack policy.
Private release windup/flight speed are not independently measured retail timing.

Barrage selects the primary foe plus at most five adjacent foes;Volley selects
at most three additional foes. Each recipient owns a separate flight and genuine
server outcome-ledger event. Hits use the existing bow armor,miss,block,damage,
conditions,adrenaline and supported reaction paths. This does not implement
all possible skills which can react to attacks. Unbound multi-attack exceptions
remain unverified. Target departure/death,weapon replacement and generation
recycling use the existing flight lifetime rules.

Selection requires live hostile same-plane actors and the shared line-of-sight
checks. Adjacent means166 units. Primary must be in bow range;secondaries may
be within bow range plus166. More than the allowed count uses nearest to primary,
then actor ID for ties. This deterministic tie-break and secondary LOS/range
policy still need retail comparison;they are not claimed recovered algorithms.
Unknown armor on a selected recipient rejects the complete batch before any
preparation removal or arrow release. Allies and non-adjacent actors are excluded.

All recipient/armor/flight/ledger proposals validate before commit. Preparations
are removed before arrows are installed,so neither Read the Wind bonus nor Ignite
Arrows is copied onto the volley. Volley also removes glyphs per the historical
2010 report;Barrage leaves glyphs intact. Runtime mirrors the authoritative
removal and clears Volley's local glyph charge counter. Arrow release and
cooldown-source completion use one World mutex transaction,sharing the
completed_bow_attack path introduced for Determined Shot. Runtime imports that
source after the callback and does not finalize it twice.
