Quests
The quest audit now includes archived E/W and W/E profession runs. It preserves

An XP-only reward storage transaction now commits character experience and the
completed->rewarded quest attempt together. Ownership, revision and attempt
checks reject duplicate/stale turn-ins. Cancellation after writes rolls both
back; missing imported XP baselines are rejected rather than treated as zero.
Network controller publishes quest removal only after the transaction commits.
This is not a full reward implementation: gold, items and learned skills must
join the same transaction before quests containing those rewards can use it.
NPC dialogue has not been connected to this operation yet.
The storage transaction also accepts reviewed learned-skill grants, checks their
skill-profile revision and adds one owned copy only when absent. Skillbar and
professions remain unchanged. XP, learned skills and turn-in state roll back
together. The XP-only packet controller rejects skill-bearing requests until
owner learned-state packets are prepared and published after the commit.
A batch reward controller now prepares the full learned-state packet followed
by new-learning219 (or existing-count220) and quest removal81. Storage conflicts
return no packets. Existing copy counts are preserved, duplicate grants rejected.
NPC dialogue callers still need wiring; gold/item rewards remain unsupported.
Gold is now supported by the storage reward transaction: it checks the inventory
revision and carrying capacity before writing, then commits inventory gold with
XP, learned skills and rewarded status. Full pockets reject the complete reward
without clipping it. Packet controllers still reject gold-bearing rewards until
inventory balance notifications/session revisions are integrated. Item grants
and NPC dialogue remain incomplete.
