NPC AI outbound reference visibility audit (2026-10-22)

Central authority already exists
Outbox::enqueue calls visible_reference before queueing OR thread-local capture.
resolve_publication applies the same filter to batches behind a publication
barrier. npc_visibility stores known NPC IDs and hides all except the peer's
published set. Per-AI broadcast loops therefore need no duplicated visibility
conditions. Ordered references queued while visible may legitimately precede
their later despawn; do not re-filter arbitrary drained/captured history.

Concrete omissions in visible_reference
Native ordinary timing53 carries actor@2 (gw_weapon_hit.h timing_2022), but is
absent from the switch. Its comment records pinned native attack assertions
requiring timing; this is an actor-reference message, not a harmless scalar.
Native projectile163 carries caster@2 (gw_skill_particle_wire.h); it uses the
direction flag0x8000, which the filter already masks, but163 is absent. The NPC
Ice Spear release path emits this reviewed projectile directly to ready peers.
Native attributed damage162 carries victim@6 AND numeric cause@10. The existing
filter intentionally checks only victim; native analysis below supports
retaining that behavior. A hidden NPC damaging a visible player loses its
separate source158 attribution, while damage162 and victim161 remain intact.
Do not blanket-filter162 causes or rewrite the source to0: that would discard
legitimate visible-victim damage/floating-number behavior without necessity.

All offsets above come from current reviewed native serializers and their
pinned-client comments, not modern capture opcode guesses or name heuristics.
This audit identifies omitted53/163 actor-reference forms; it does not assert
each necessarily crashes every client. No official client or logger was used.
