player/NPC scopes, rejects a future health clock, settles current player health,
requires positive precise/current health, then reuses existing plane/range160
and navigation reachability. The lookup nearby_npc_name keeps its current
semantics for unrelated consumers. The native service app path uses this gate
for panel opening, transaction admission and pre-CAS recheck across crafting,
merchant and collector. Generic collector fallback must share the same gate.

actual World::kill while retaining panel/range, proving name lookup alone is
insufficient and admission must reject without inventory change. It also checks
stale player/NPC generation, wrong instance, and earlier health clock. This is
mechanics coverage, not a network harness or actual Accounts/CAS test.

Remaining transaction limits: World range/lifetime checks and SQL CAS are not
one atomic distributed lock. Static Arthur does not move but other sources can
change between released World checks and persistence. Avoid holding a World
lock through account callbacks because those paths can re-enter World.

is closed until reconnect. They are not durable request nonces across a new
authenticated connection. Current-opening snapshot/revision CAS and fresh IDs
prevent duplicate commits within the admitted connection/opening contract.
