INVENTORY SECTION: AUTHORITATIVE REQUIREMENTS AND EVIDENCE

Scope: supported native2022 client. Local May2021 wiki under Desktop/gw/Wiki/
wiki.guildwars.com/wiki is read-only reference. Mechanics from these pages are
not proof of a raw protocol modifier ID. Native item decoder audit is separate.
No item instances, ownership, upgrades, sale prices or captured provenance are
invented by this rules helper. Every live mutation needs owned persistent items,
transaction/CAS, atomic debit plus result, bounded wire and reconnect restore.

Bags/storage
  Bag.html: two equipped bags,5base slots. Nonempty bags cannot be unequipped,
  traded or stored; nested nonempty containers impossible. Rune_of_Holding:
  bag5->10 only. Superior_Rune_of_Holding: bag5/10->15. Rune_of_Belt_Holding:
  belt5->10 only. None works on EquipmentPack/backpack/storage. Holding runes
  cannot be salvaged back; invalid upgrade consumes nothing.
  Equipment_Pack.html: sizes5/10/15/20, weapons/armor/costumes only, no equipment
  customized for another character. Do not treat it as generic bag storage.
  General move/split admission now checks native type1/index4 packs, including
  both legs of swaps and shared storage-transfer proposals. Item categories
  use local gw/GWCA/Constants.h ItemType (lines95-100): weapon/offhand classes,
  five armor types, costume headpiece44 and costume45. Unknown types reject.
  Synthetic tests in tests/inventory.cpp verify atomic rejection, allowed
  categories, relocation persistence and bank-withdrawal admission. Pack
  admission also uses explicit character context passed through inventory
  and storage policies. Present-empty customization is uncustomized; absent
  metadata is unknown and rejects pack admission. Nonempty owners must match
  the current character. Unequip and displaced equipment swaps use the same
  rule. Synthetic inventory/equipment tests cover owner, unknown metadata,
  alternate-character withdrawals and both swap legs. Existing saved
  profiles are not reclassified or silently repaired by this admission rule.
  Ground pickup and trade now filter both empty capacity and merge targets
  through the same pack admission. Existing allocation order is unchanged.
  Pickup receives the session character name; trade reads both recipient names
  within its database transaction, independently of caller offer data. Tests
  cover material-only capacity and legacy invalid stacks, exact owner matching,
  eligible gear, and atomic two-account database rejection/commit.
  Equipment_Pack.html and official Game_updates/20090423.html establish the
  item-category restriction. Reviewed native packet/lifecycle notes do not
  establish an automatic-placement exclusion for packs. User feedback page
  Feedback_User/Gwynna_Vive/Equipment_Pack.html describes weapons filling the
  pack last; this is corroboration only, not native/official ordering proof.
  Collector exchange applies shared admission to the finalized reward after
  owner customization, for both merges and free slots, preserving allocation
  order. Exact Brownlow pouch/egg tests reject pack-only capacity and legacy
  egg merges without debit or persistence calls; Savich owner-customized armor
  remains eligible. Later ordinary-bag placement retains exact trophy debit.
  Xunlai account-shared bank entitlements, material stack slots and permissions
  must remain separate from character bags. Atomic character+bank CAS must
  prevent duplication, stale revisions, arbitrary tabs and container IDs.
  UI container presentation IDs must never become owned durable items.
  Trade admission rejects interaction0x100 in addition to existing restricted
  classes and equipped/installed placement. This uses direct trade evidence:
  pinned Toolbox InventoryItem.h:58 IsTradable and InventoryManager.cpp:2633
  CanOfferToTrade, not an inference from the drop predicate. Header SHA256:
  dfb638cbaf2a1b6db93a4cdc060d56208c7b4f9e9178c1d4cedaba993ee7b8b7.
  Local Trade.html164ff documents nontransferable bonus/event possessions.
  Shared offerable(profile,id) supports UI and final transaction admission;
  customization alone remains tradable. Tests cover each participant, all
  individual interaction bits, existing restrictions and atomic database
  rejection preserving items, gold and inventory revisions on both sides.

  an armor upgrade or a generic use-heal. Nonstackable; post2013 cannot identify,

Identification/salvage
  Identification_Kit.html/Salvage_Kit.html/Expert_Salvage_Kit.html: typed kit
  uses, eligible item/identified state, actual modifiers/value and native dialog
  sequences need audit. Basic versus upgrade extraction and destructive risk
  must be explicit. No fabricated rare material/result distribution. Each
  attempt debits one kit use and consumes/transforms target only in one owned
  transaction. Perfect/retention probabilities need reviewed kit-specific data.

Consume/equip/drop/pickup/gold
  Typed consumable effects, durations, stacking, cooldowns and campaign/map
  restrictions require reviewed definitions. Generic use cannot simply delete
  arbitrary items or succeed without an effect. Actual equip moves must respect
  type/slot/profession/requirements/customization and resource modifier changes.
  Unequip requires available valid storage; do not overwrite occupied slots.
  Drop debits durable inventory and creates explicit owned world item identity;
  pickup reconciles world generation/range/ownership/quantity and capacity in
  one transaction, preventing double pickup. Gold stack/drop and character/
  bank maxima must be independently reviewed, never inferred from ordinary
  item quantity. Prices cannot be inferred from trader supply/demand guesses.
  Destroy needs genuine client confirmation semantics and durable removal.

Completion gates
  Every operation: real captured or intentionally provisioned private item,
  correct native client request/response, ownership + stale generation checks,
  invalid request no debit, CAS rollback, reconnect persistence, duplicate
  replay resistance and private live UI proof. Tests/helpers alone do not
  establish an end-to-end completed Inventory section. Current helper is not
  yet bound to raw decoded upgrades or live equip state.

Offline captured inventory importer (tools/items/import.cpp)
  Usage: items_import CAPTURE_JSONL CHARACTER_GUID ACCOUNT_GUID character|bank OUTPUT
  Reads only a supplied file. Never opens a client, logs in, or writes the account
  database. Account GUID is an explicit operator ownership binding, not account
  ownership authenticated by the observation itself. Character GUID must match.
  Exports the current native inventory codec plus an ownership sidecar; consumers
  must independently enforce account/character ownership before any DB import.
  Exact supported observer provenance is mandatory. Schema1 is rejected because
  it omits four weapon-set pointers/active set and named352 fields. Schema2 needs
  wire_unknown1, wire_dye, wire_materials, wire_unknown2 for each definition and
  weapon_sets[{weapon,offhand} x4]/active_weapon_set for character snapshots.
  No unknown values or set references are invented. Captured native modifier
  terminator is stripped once through the audited adapter. Bag/item ownership,
  references, bounds, metadata, and codec roundtrip are validated. Unsupported
  material/unclaimed bags are outside this carrying/equipped or bank domain.
  Nonzero container references without an owned placed container definition are
  rejected; the present codec cannot represent an unplaced bag-container item.
  No real input snapshot is presently available for an end-to-end import test.
