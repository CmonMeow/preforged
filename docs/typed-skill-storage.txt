Typed skill storage migration — 2026-10-09

NetworkServer::characterSkills and saveSkillbar now call NetworkManager typed
methods directly. Manager admission remains serialized with a three-second
request deadline. Accounts reads/updates skill profiles directly from SQLite,
without tab/hex request or response serialization on the production path.

Offline skill get/bar-save adapters share those same implementations. Full
profile import remains an offline operation. Saving a bar changes only the
profile and revision; the captured source hash is preserved. Existing learning,
profession and ownership validation applies. The SQL transaction rolls back if
the request expires after update and before commit.

Validated by rebuilt network_lifecycle, quest_accounts, development_accounts
and accounts_lifecycle tests: all four passed. The isolated quest-accounts
fixture also covers missing profiles, foreign ownership, stale revisions,
invalid skill IDs, cancellation at the final pre-commit check and profile
preservation. No production account database was changed by these tests.

The currently running host has not yet been replaced. Linking/publishing and
private-client smoke verification remain required before claiming live use.
Other application operations still contain legacy serialization; this is not
completion of the overall architecture migration.
