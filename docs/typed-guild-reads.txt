Guild cape, guild faction, and tournament reward points are native typed reads through NetworkServer -> NetworkManager -> Accounts. Shared helpers in accounts_guild_reads.inc also serve offline adapters. Each read checks owner existence in a transaction and checks cancellation before returning; cancelled results carry no value. An absent cape remains an absent optional value, while absent balances return zero only for an existing account. Cape fields are decoded/validated, balance fields are bounded to uint32. Guild faction applies existing daily decay atomically; cancellation after the update rolls back the balance and day together. Tests compare native cape encoding to offline values, verify nonmember/account isolation and cancelled reads, and verify cancelled decay does not persist. Remaining production Operation dispatch: registerAccount, validateSession, issueTicket, login, logout, authenticateTicket, guild, guildCommand, purchaseGuildCape, purchaseGuildTrim. Custom NetworkClient transport stubs remain incomplete.
