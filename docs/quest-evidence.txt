Quest content and capture evidence
==================================
The local wiki extraction contains 1,424 quest pages representing 1,306 unique
titles, including Clear the Chamber. Alternate/redirect pages must not become
duplicate runtime quests. All extracted pages have objectives; 1,172 have a
Dialogue section. The extraction reports zero failures, which does not prove
that the local snapshot contains every quest. tools/quests/extract_wiki.py produces the generated catalogue at
build/reports/wiki-quest-catalog.json with source paths, hashes and section lines.
Objectives, requirements, rewards, dialogue and walkthroughs are reference
content. Native quest IDs remain unmapped; these entries are not runtime rules.

Implementation policy: use the local wiki as the quest-content reference rather
than requiring players to recapture published objectives, rewards and dialogue.
Use packet/quest-state evidence to map native IDs, dialogue branches, acceptance
and completion transitions, and instance-specific creature spawns. Keep each
mapping tied to its source; a nearby creature appearing after acceptance is not
by itself proof that the quest spawned it.

The world collector source records quest_snapshot_changed with active quest ID,
raw quest state, text and map references. npc_visibility_changed references the
quest snapshot revision. Appearance near acceptance is correlation: distinguish
baseline map population from quest-conditioned population before importing it.
The README still marks this extension experimental and awaiting live validation.

Named NPC packet interaction files currently preserve incoming packet context.
Outgoing dialogue choices and joining quest snapshots to those files remain
incomplete. Capture timestamps/instance epochs, quest revisions and NPC identity
must be retained when implementing that join. A wiki walkthrough can explain an
observed transition but cannot establish the native packet layout or quest ID.
