Shared mechanics
----------------
An OwnedPreparationContact contains exact source Scope and owned Registry
Entry(effectID,skill,rank,applied/expiry). Snapshot qualification validates
category,cause,duration,rank and actual accepted Owned weapon. Bows qualify
for allthree;other martial types qualify only for Apply Poison. Caster
weapons cannot become martial merely by holding a physical damage code.
Current owned parser/controller limits still apply to unsupported families.

Arrows snapshot the active preparation at weapon release,as existing Read
the Wind/Ignite delivery does. Ordinary and skill bow queues share that one
capture point. Melee contacts sample the current owned entry. Target
enchantment qualification is sampled at impact from actual owned player/NPC
effects; unknown NPC enchantment presentation fails closed. Arrow snapshots
survive preparation replacement/expiry but remain subject to existing source
lifetime/living/equipment and recipient lifetime guards. Barrage/Volley remove
preparations before queuing arrows. Release-vs-impact preparation phase is an
explicit project policy; these local pages/captures do not prove retail phase.

The same landed-contact path excludes miss,block and Illusionary replacement.
Apply Poison commits after each attack's own condition,including Cyclone's
independent actual recipients. Source copies do not convert nonhits into hits.
Condition immunity suppresses the condition without discarding accepteddamage.
Condition duration/fresh UI-ID capacity is checked before primary damage;
existing scoped condition/Fragility/death authorities own actual commits.

Melandru adds its conditional bonus only when the impact recipient has an
actual enchantment,and applies Bleeding on every accepted surviving hit.
Kindle transforms a copy of the actual weapon's element before primary armor,
physical-only Barbs/Mark of Pain qualification and Conjure element checks.
Fixed-damage attack replacements keep their existing primary damage kind;
the separate qualifying Kindle Fire hit still uses its own armor/protection.
Primary armor admission and separate Fire preflight require known Fire armor;
unknown authority rejects before damage. The extra Fire hit uses shared armor,
Cracked Armor/bonuses,elemental defenses,flat reduction,cap and Fire-vulnerability
policies. It adds no attack event,critical draw or attack adrenaline. Received
damage reactions remain normal. The primary contact owns death cleanup.
Shared contact order is primary,Kindle extra Fire,then existing Conjure;this
secondary ordering is project policy pending isolated retail evidence.

Runtime uses existing preparation type19 lifecycle:2sbase/noaftercast,shared
Expertise payment,12srecharge,category replacement/expiry,proper18/24s status,
cancel/interrupt and native738 only for Kindle. Missing/lost status mutation
capability fails closed for the new family instead of caching an unowned buff.
