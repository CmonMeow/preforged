Identity/prerequisite

Require Prophecies/pre-Searing/core primary and that primary's rewarded test.
Further Adventures54 and Unsettling Rumors62 are NOT prerequisites (local wiki).

quest cycle are mandatory. Private tokens are not recovered retail dialog IDs.

Objective authority
Only a persisted selected secondary1..6, different from primary, qualifies.
Its corresponding training quest must already be rewarded:
Warrior75, Ranger76, Monk74, Necromancer72, Mesmer71, Elementalist73.
A trial grant, unlocked profession bit, requested secondary, controller preview
or failed secondary save never qualifies. This preserves missing trial blockers;
79 does not bypass incomplete pet/minion/hazard quests.

Accept before/after selection
Accept79 normally creates active state and publishes exactly one native72 add
and75 details. If a valid trained secondary was selected before acceptance,
reconcile immediately after acceptance save using the same completion path.
When accepting before selection, invoke only after successful secondary commit;
publish the profession state before quest objective update. Failed save produces
no completion. Expected quest cycle and revision prevent delayed completion from
touching an abandoned/reaccepted attempt.

Completion and crash recovery
Prepare native83 objectives and76 marker, save active->completed, then publish.
Never send72 or79 for an already present quest: original83 emits QuestUpdated,
whereas79 emits QuestAdded. This is independently pinned by existing native
quest serializers, not inferred by subtracting modern logger opcodes.
On reconnect first restore the durable quest once, then reconcile an active79
against the durable selected profession. A crash between profession commit and
quest commit is recoverable; a crash after quest commit restores completed state.
An Armin interaction can retry failed reconciliation. Completed/rewarded attempts
are idempotent and produce no repeated objective update or reward.

Storage fence
Inside save_quests' existing SQLite transaction, detect changed79 progress.
Validate exact one-record legal acceptance/abandon/completion transitions against
the prior persisted profile; read current persisted skill profile for completion.
Reject direct insertion of completed/rewarded79 and erased history. This avoids
a new wire/request/schema field while preventing generic SaveQuests bypass.
Reward79 must have exactly250XP and no item/gold/skill/unlock side effects, valid
completed progress, rewarded primary/training and persisted chosen secondary.
Existing revision-checked completed->rewarded plus XP transaction guarantees
once-only payout. Failed/stale/timeout reward emits nothing and changes nothing.
