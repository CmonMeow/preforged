Guild snapshots now use NetworkServer -> NetworkManager -> Accounts without Operation/string dispatch. Shared read_guild serves production and offline adapters. A transaction reads owner, guild header and roster consistently; existing accounts without a guild return absent state. Native checks validate guild/member identities, UTF-16 bounds, hall range, roster size<=100, unique membership, owner membership, and exactly one leader. Cancellation is checked before admission, during roster iteration, and before commit, returning no partial state. Tests cover native roster/announcement matching, foreign guild isolation, missing owners, cancellation with a partially read roster, ambiguous leadership rejection, and a full100-member guild. Invitations are handled by guild commands rather than exposed in the existing snapshot schema; this migration preserves that contract. Remaining transitional calls: six authentication/session operations, guildCommand, purchaseGuildCape, purchaseGuildTrim.
