Native GW2022 inventory and account bank integration
==================================================
Production APIs: src/runtime/gw_inventory.h and gw_storage.h. No official
inventory capture currently exists; captured character appearance is not an
item definition and must never become invented armor/modifiers/prices.

Persistence contract (root implementation):
  gw-character-inventory-get accountUUID characterUUID
  -> 0 if absent, otherwise revision TAB encodedProfileHex.
  gw-character-inventory-save accountUUID characterUUID expectedRevision profileHex
  -> newRevision. Ownership checked and revision CAS in transaction; absent
     revision0 initializes explicit private baseline, never replaces on login.
  gw-account-storage-get accountUUID -> 0 or revision TAB encodedProfileHex.
  gw-storage-transfer-save accountUUID characterUUID charExpected bankExpected
       characterProfileHex bankProfileHex -> charNewRevision TAB bankNewRevision.
     BOTH ownership domains and BOTH revisions validated/updated in ONE
     transaction. Never save one half, never publish packets before commit.
Character FK deletion cascades only character inventory; account bank persists.
Only trusted server proposals may supply blobs. Client requests never contain
a profile or acquire bank permission by naming its bag ID.

Inventory baseline is empty backpack20 + equipped9. Bank baseline is empty
first ordinary Xunlai tab20; unlocking it is private server policy, not a claim
that an official capture proved its purchase. Storage visibility and access
require authoritative chest interaction. No global chest-open flag across users.
Restore only into newly initialized client inventory, never replay occupied
placements. Definitions precede locations, bags precede definitions. Owner only.
On denial use individual item reconciliation, no complete occupied replay.
