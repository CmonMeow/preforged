NPC AI configuration and evidence boundary, 2026-10-28

Native implementation guide. Final typed-immediate build97509 was running when
this document was saved; consult the root's final report for verified results.
No rendered-client behavior or measured retail patrol/stats claim is implied.

Existing usable loop
Controllers retain exact source Scope (instance, actor, generation), home pose
and authored speed/acquire/follow/leash policy. Idle movement is opt-in. Generic
hostiles acquire candidates in their authored acquisition radius; committed
positive damage can provoke them within follow/home leash even outside acquire.
Memory retains observed foes; no group IDs or retail threat weights are invented.
Supported attacks/casts respect action, resource, geometry and lifetime checks.
Losing targets or reaching the home leash starts return; return has priority
over idle, and patrol resumes after return and pause. Knockdown, windup and
aftercast constrain actual movement budgets. Navigation/LOS/collision remain
authoritative; routed corner positions are published in order. Actual client
interpolation of that packet sequence is not established by native tests.
Unavailable routes are distinguishable from deferred observations, zero budget,
valid detours and unsupported layers; no unmeasured combat timeout is supplied.

Configuration APIs
1. configure_npc_hostile_ordinary(FlarePolicy,ordinary::Reviewed,now): existing
   hostile NPC with known living Health plus explicit attack damage/type,
   timing/range/delivery evidence. No Energy or fake spellbook is required.
2. configure_npc_flare_ai / configure_npc_elemental_ai: reviewed spell-capable
   NPCs using the existing projectile/elemental effect drivers. Rank, spellbook,
   resource observations and relevant target armor/Overcast observations are
   required by the selected effect. Merely listing a skill is not effect support.
3. configure_npc_immediate_ai(FlarePolicy,vector<activated::Reviewed>,now):
   existing hostile NPC with living Health and known Energy/regeneration; each
   Reviewed record contains Slot, canonical ShadowPlan and evidence. Today only
   Vile Touch155 passes the complete consumer constraints. It is a non-spell
   skill: pinned2022 type10, not modern reference type38. Its inactive raw
   Overcast field is ignored using the native special bit. Dark Pact133 sacrifice,
   Obsidian Flame219 active Overcast and life-steal followups remain rejected.
   No immediate spell effect support is established by the new155 tests.
4. configure_npc_wander(source,wander::Policy,now): enroll an existing generic
   controller with bounded offsets, pause and leg timeout plus policy evidence.
   It does not assign Health, armor, Energy, rank, allegiance or attack data.
   Generic APIs reject quest-owned actors and competing control ownership.
5. arm_grawl_melee(owner,cycle,now), then arm_grawl_wander: existing quest75
   roster only. arm_brood_caster then arm_brood_wander: existing quest49 only.
   Both preserve owner/cycle/exact lifetime and require actual health loss;
   proximity alone does not trigger these quest-owned encounters.
6. npc_ai_coverage reports placed/reviewed/active/unknown-health/wandering counts.
   npc_pursuit_movement_snapshot(source) reports timestamped movement outcomes.

FlarePolicy is currently the shared motion-policy type, even for ordinary and
immediate controllers. Its legacy flight fields must validate, but immediate155
does not launch a projectile. Do not interpret that validation as flight evidence.
Ranks and authored values must carry provenance. Unknown metadata stays unknown.
configure_activated_skillbook / begin_activated_skill on LiveActor provide typed
spell/non-spell action authority with one Energy/recharge/aftercast ledger.
Existing configure_spellbook / begin_spell remain spell-only wrappers. Effects
must still use a World driver, not directly bypass its scoped damage admission.
