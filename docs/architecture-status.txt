Architecture status audit, 2026-10-04

Production root: Desktop/gw-server. Source in src, tests and synthetic fixtures in tests,
developer tools in tools, runnable artifacts in bin, disposable build results in build,
persistent account state and private captures in data. Sibling projects are reference-only.

Implemented foundation
- src/apps/server_host.cpp owns one native host and visible console lifecycle.
- src/network/network.h and network.cpp define NetworkManager, NetworkComponent,
  NetworkServer and NetworkClient. Server/client derive from the common component.
- NetworkServer owns portal/auth listener threads. The auth adapter owns world sessions.
  Original Guild Wars 2022 clients connect directly to these listeners.
- NetworkManager serializes trusted application calls into Accounts using a timed mutex
  and request deadline. No local RPC hop, registry, forwarding host or DLL service loader.
- NetworkClient exposes virtual request plus named account/character/inventory/social
  operations. Transport is intentionally FW_UNAVAILABLE until a custom client is built.
- Native lifecycle tests exercise bind failure rollback, restart, duplicate start, live
  connectivity and future-client virtual request dispatch. These are evidence for the
  foundation, not evidence that all game services or public hosting are complete.
