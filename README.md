# Guild Wars 2022 server

## Quick start

This is an early private-server development project. It is not a complete or production-ready Guild Wars server.

Requirements: Windows 10/11 x64, Visual Studio 2022 or newer with the Desktop development with C++ workload, and CMake 3.24 or newer. The project builds as native C++.

1. Clone this repository and open a terminal in its root.
2. Build with `cmake -S . -B build -A x64` and `cmake --build build --config Release`.
3. Run `START SERVER.cmd` and keep its console open. Ctrl+C stops the server.
4. In a second terminal, run `START CLIENT.cmd` to launch the local test client.

The development login is `test@example.test` / `test`. Players must supply their own compatible client and `Gw.dat`; neither is included in Git. Put them in `bin/client` for local testing. Server binaries, databases, captures, and logs are also local-only. See `docs/sharing-and-setup.md` for setup and licensing details. The server writes `data/logs/server.log`.

To run tests, use `ctest --test-dir build -C Release --output-on-failure` after building.

## Project status

This is an early private-server development project, not an official ArenaNet product. It is unfinished and intended for local testing. Read `docs/sharing-and-setup.md` before distributing builds or client files.

The development server currently provisions local accounts with campaign access for testing. This does not verify game ownership or connect to ArenaNet services.

Run **START SERVER.cmd**, then **START CLIENT.cmd**. Local credentials: `test@example.test` / `test`. Keep the server console open; Ctrl+C stops it. The runtime log is `data/logs/server.log` (latest run).

The server console prints its process ID and exact executable SHA256. `bin/server_host.exe --build-info` prints the same identity without starting listeners. The entrypoint compile timestamp alone does not identify gameplay changes linked into the core.

Current live verification (2026-10-09): the updated host passes all 126 tests. The 2022 client passes login, character selection, world entry in Lion's Arch, keyboard movement and ground-click movement. Xunlai gold deposit/withdrawal and armor deposit/withdrawal/re-equipping passed through the native UI. Campaign-owned panes I through IV are provisioned without replacing existing bank items, funds or purchased panes; pane IV also passed a transfer after client relaunch. Reports are in `build/reports/`; implementation notes are in `docs/storage-pane-provisioning.txt` and `docs/typed-inventory-writes.txt`.

The full private server is unfinished. Custom-client transport, remaining typed-operation migrations, broad skill effects, quest behavior, NPC AI and complete item/vendor behavior still need implementation and verification. A passing smoke test establishes only the tested login/world/movement sequence.

Production code is in `src/`; tests and synthetic fixtures in `tests/`; developer utilities in `tools/`; runnable files in `bin/`; disposable compiler/test output in `build/`; private captures and persistent state in `data/`. No sibling project is a build dependency.

Local development accounts unlock Prophecies, Factions, Nightfall and Eye of the North. Travel still requires prepared map geometry and an arrival point; 395 maps are currently prepared. Most uncaptured arrivals are labelled development ground placements in `data/gw/map-support.json`, not official portal spawns.

Exploration reveals a quantized 3×3 area around the server-owned player position, sampled every 200 ms. Coordinates come from the pinned 2022 world-map rectangles and extracted terrain bounds, with 3,072 game units per cell and inverted Y. Progress is saved per character and continent under `data/gw/character-settings` and restored on map entry through the client's compressed exploration format. Live checks matched 30 saved cells in map163 and restored 73 cells after a clean reconnect in map57 with zero differing bits. Regression tests cover compression boundaries, concurrent sessions and save recovery. Malformed saves are preserved as `.corrupt-*` siblings; storage errors are logged and leave the session playable without overwriting unreadable progress. Primary exploration rectangles are usable in 323 of the 393 prepared maps. Position-based reveal is suppressed elsewhere; custom guild-hall compass textures do not represent a separate persistent fog grid. The algorithm, formats and limits are documented in `docs/exploration.txt`. The obsolete exploration logger and raw exploration captures have been removed.

One C++ server executable owns the portal, auth and world listeners. Account and character requests are direct in-process calls through NetworkManager. There is no registry, DLL service loading or forwarding process. NetworkServer and the future NetworkClient derive from NetworkComponent. The custom-client transport methods remain explicitly unimplemented.

NetworkServer passes typed ServerSettings directly to its listeners and owns their startup and shutdown. The host alone handles console shutdown. The network lifecycle test covers invalid/conflicting ports, partial-start rollback, connections to all three listeners, and stop/restart within one process.

NetworkClient exposes typed application methods but currently returns unavailable; it has no working remote transport. NetworkServer calls typed NetworkManager/Accounts methods directly for skills, attributes, secondary profession, quests, progression, factions, inventory, storage, trade and character name/map/experience reads. Other operations still use the transitional in-process request adapter. Tests cover both direct dispatch and the remaining adapter boundaries.

Authenticated connections have a five-minute idle timeout refreshed by complete parsed messages, including keepalives. Active sessions no longer have a fixed 30-minute disconnect. A simulated-clock test covers a day of activity and subsequent idle expiry; a full-day live soak is still pending.

World/player identities are reserved for pending transfers and active world connections. Leaving releases the reservation; empty districts leave no permanent directory entry. NPC IDs are excluded, and public/private worlds share collision checks. Allocator tests cover 70,000 sequential reconnect reservations and 800 concurrent reservations; three live character-select/re-entry cycles also passed. These allocator tests are not equivalent to that many network clients.

The existing 2022 client still requires its client-side login API adapter DLL (`bin/client/bridge/GwLoginClient.dll`). It connects directly to this server; removing that adapter is unfinished compatibility work. It is not another running server.

## Current limits

Development commands `/travel <map ID>` and `/tp <map ID>` share the server's map and client-DAT asset checks. When a map has a DAT binding but no captured spawn, the server uses a walkable point nearest the mesh center; without a mesh it uses the map origin and logs that collision is unavailable. A logical map with no client-DAT asset is rejected before changing the character's saved location. `data/gw/recovery-map.txt` selects the validated city/outpost used if a character's saved map lacks client data; the current recovery destination is map 248. A live 2022 client completed travel through maps248,148,163,164,165,166 and55 with their captured NPC populations. Maps163–166 use reviewed official-client loading arrivals validated on the 2022 navigation mesh. These are default arrivals, not portal-direction spawn mappings. Coordinated party travel, NPC interactions and quests remain unfinished.

Movement sends the 2022 agent speed and elapsed-clock packets as well as destinations. Live tests confirmed running animation during a ground click; the forward-key release correction fell from about 280 to 3.5 world units after fixing the missing clock. Further live tests covered five seconds backward, two seconds strafing each way and seven seconds forward, with release corrections below one world unit and no disconnect. Evidence is in `build/client-check/long-hold.log`. The clock has regression coverage for fresh connections, load transitions, delayed ticks and a simulated day. Click routes preserve elapsed time across navigation segments and simplify visible same-plane sections. Collision-edge sliding now preserves navigation planes, uses the retail minimum tangent speed, and clears stale local prediction on first contact. Two final seven-second private wall tests stayed connected without the earlier large mid-slide jump; release corrections remained 8–14 world units. All 27 native tests passed. Evidence, including earlier failed runs, is in `build/reports/corner-movement-validation.json`. Wall-tip handoff now renews finite owner goals after contact ends, until fresh free-space input restores local prediction; a connected wall-tip regression verifies continued movement, handoff and release. Contact endpoints now use physical boundaries, and connected cells touching a corner supply legal tangent candidates without granting unlinked floor access. A two-degree near-head-on stability policy stops tiny tangent sign changes from being amplified; held input remains active. Unchanged held refreshes no longer repeat stop/position corrections. Native regressions pass; latest live animation smoothing and autorun cancellation are not fully validated (`build/reports/wall-tip-validation.json`). Click-route segment timing and multiplayer smoothing still need further work.

Party state and 2022 invite-by-player-ID, accept, cancel, refuse, leave and kick handlers are integrated. Party chat, callouts, readiness and compass drawings route through membership; simulation tests verify isolation and invitation expiry. Two 2022 clients have verified name invitation, acceptance, rejection, cancellation, party chat delivery and leaving through the normal UI. This used two sessions of the same synthetic test character; separate-account validation remains open. Name invitations are supported through opcode159 and /invite. Party travel remains unimplemented. Party capacity now comes from the hash-pinned 2022 AreaInfo table for all877 maps: pre-Searing Ascalon2, Lions Arch6, GToB8. Extraction verifies campaign/continent/region/type fields against the existing map catalog. Party-state tests fill each supported town to its limit and reject another member; a six-client live party test remains pending.

Map 248 (Great Temple of Balthazar), map 148 (pre-Searing Ascalon), and map 55 (Lion's Arch) have default entry points checked against the 2022 navigation mesh and live client. Evidence and limitations are recorded in data/gw/spawn-provenance.json. Entry uses config/spawn-points.txt each time, without restoring logout coordinates. Per-portal spawn selection and other maps remain incomplete.

The 2022 client has completed character creation, deletion, selection and entry into pre-Searing Ascalon in live tests. Created characters retain their appearance and level; armor appearance renders in the world. Usable inventory, equipment statistics, skills, NPCs and combat remain incomplete. Recognition/framing of 189 outgoing messages does not mean all corresponding gameplay actions are implemented; unsupported actions are logged explicitly.

Player-follow (2022 opcode 49) now uses server navigation and cancels on manual movement, /stuck, or target departure. Simulation tests cover pursuit, arrival, resuming, agent-ID reuse, and bridge traversal. Two local 2022 clients verified town visibility, movement and follow in Ascalon. The 100-unit stopping distance is local policy. NPC interactions are not covered by this handler.

Following callouts (kind 3) announce the current server-owned follow target in solo-party chat, preserving Unicode names. Calls for cancelled, departed, or different targets are rejected. These use English literal messages; Ctrl+Space and the displayed callout were verified with two local clients. That test used the same synthetic character in both sessions, not separate accounts. Remote player level is now included in both live joins and initial snapshots; both directions displayed level 1 in the live test. Level progression remains unimplemented.

Server health updates now reach other players, and later arrivals receive the current health snapshot. Energy remains owner-only. Simulation tests cover changed health, late arrival, and invalid updates preserving the last valid state. A damaged remote target bar has not yet been verified live; combat and damage generation remain unimplemented.

Ctrl-click health and energy now produce party chat from server-owned resource values, verified in the live 2022 client. Morale and experience callouts use the same party-only path and have regression coverage. Newly created characters persist zero experience; older/imported characters retain an explicitly unknown value until progress is captured or implemented. Unknown XP is not announced in party chat (the initial client stats packet still uses a zero placeholder). Importing a replacement character profile clears uncaptured XP. XP rewards and leveling are not yet implemented. Callout text currently uses English literal messages rather than localized retail templates.

Reviewed NPC populations load from `data/gw/npcs.txt` at startup: 142 static actors across eight maps, including 38 actors from the explicitly reviewed claimed/upgraded Isle of Meditation capture. Six player miniatures were excluded from pre-Searing Ascalon using known GWCA model identities and captured definition flags; populations are never merged across instances. Startup checks model-record bounds, scale, duplicate IDs, conflicting definitions and navigation positions. Each instance initializes its population once; player IDs skip NPC IDs. NPC definitions precede spawns, sent after local player setup. All eight maps completed live world entry with their expected three NPC packets per actor. Visible names and models were checked in Great Temple of Balthazar, Lion's Arch and Isle of Meditation; the other five maps had entry-only checks. The preserved log and per-map results are in `build/reports/npc-live-validation.json`; capture selection and exclusions are recorded in `data/gw/npc-population-provenance.json`. Lion's Arch now includes two additional verified same-instance observations: a Lionguard and a second Xunlai Chest. A live 2022 test verified clicking a chest, walking into range and opening the Vault Box without the former backpack-container assertion. NPC approach and storage interaction are implemented; vendors, quests, NPC movement and combat remain unfinished.

The standalone native skill catalogue and skill-bar module use 3,433 raw records extracted from the pinned 2022 executable, including internal records that are not player skills. Fractional activation times and encoded energy costs are preserved. Verified 2022 packet fixtures cover skill-bar edits, learned-copy counts, ordered profession initialization and authoritative rollback after rejected optimistic client edits. Validation covers ownership, slot bounds, explicit learned-copy availability, professions, campaigns, one elite and at most three occupied PvE-only slots, including distinct Signet of Capture copies. The module now handles live edits and persistent character profiles. Captured A V E Y learning, bar and 200 attribute points restore in the 2022 client. Attribute allocation, bar edits and secondary-profession changes use ownership checks and revision-controlled saves. Four healing spells implement energy consumption, activation, cancellation and recharge; other gameplay effects remain unfinished. No imported character is granted a guessed skill bar or learned-skill list. The bounded native integration blueprint is in docs/skill-integration.txt.

The separate native observer in `bin/skills` reads the supported official client without injection, client writes, UI control or login traffic. Its current character capture has 1,081 distinct learned skill IDs and 1,233 account unlocks, with an exact GUID/name match to one imported main-account character. Compared with the normalized 2021 wiki baseline, the account has 1,233 of 1,235 ordinary unlocks; the missing two are Signet of Recall and Purifying Veil. The observed character has 1,027 ordinary and 54 PvE-only skills, leaving 248 base IDs from that older list. This is one character's learning, separate from account-wide availability. The observer also records the equipped bar, copy identities, professions and 51 genuine attribute slots; the matching GWCA header's 54-row declaration incorrectly includes internal trailing state. The captured bar passes the native 2022 validator. Its full modern constant-table dump preserves all 3,495 records and matched the exact executable table byte for byte; animation/icon/string references are captured, but sounds and live cast/effect events remain unresolved. Usage, version limits and player/hero observation plans are documented in `docs/skills.txt` and `bin/skills/README.txt`; the identity-redacted coverage report is in `build/reports/skill-coverage.json`.
